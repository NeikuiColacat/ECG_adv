# Instruction Update Rules

Keep durable guidance with its owner instead of copying it into every skill.

## Good Changes

- Clarify a real scope/trigger or remove an obsolete path.
- Fix a demonstrated instruction conflict or repeated decision error.
- Deduplicate common rules into AGENTS and keep non-obvious procedure details.
- Preserve the source-of-truth pointer and all safety/scientific invariants.

Review requests are report-only. Apply explicitly requested project instruction
edits directly; ask only for a material unresolved choice or expanded authority.
Session/worktree/file deletion, global state and experiment actions retain their
own approval gates. Do not infer those permissions from documentation work.

## Avoid

- Generic advice, temporary run/PID/status facts or copied experiment results.
- Mandatory extra approvals for edits already authorized by the user.
- Universal report templates, fixed step counts or speculative defensive rules.
- Broad reorganization unless requested; optimize the existing owner first.
- Removing provenance, identity or resource safeguards merely to save tokens.

## New Skill Bar

Add a skill only for a separate reusable workflow with a recognizable trigger,
concrete demonstrated benefit, and no adequate existing owner. A one-line rule
belongs in AGENTS instead. Prefer no new skill to another overlapping router.

Verify descriptions, local references, shared copies and realistic decision
cases. Report the actual changes, reason and checks; a full printed diff or
empty "no new skills" section is unnecessary.
