# Retrospective Update Rules

## Acceptable AGENTS.md Changes

- Add a short "do X when Y" rule that prevents repeated friction.
- Tighten an existing shared-server, experiment, or git safety constraint.
- Add a 2-4 line preferred command pattern after repeated manual correction.
- Add a one-line pointer to a tiny skill or active evidence registry.

## Reject These

- Large reorganizations of `AGENTS.md`.
- Vague advice that does not change the next agent's behavior.
- Rules based on one low-impact event.
- Long lists of prohibitions that make startup context heavier.
- Temporary experiment details that belong in a handoff or evidence registry.

## Tiny Skill Bar

Create or update a skill only when all are true:

- The pattern is reusable and has a recognizable trigger.
- It would have saved real time in at least two similar sessions, or one very
  expensive session.
- It is more useful as a procedure/checklist than as a one-line `AGENTS.md`
  reminder.
- It does not duplicate an existing skill.

When in doubt, propose a report-only update and ask for approval.

## Retrospective Output Quality Bar

Each proposed durable change must include:

- **Evidence**: specific session, handoff, doc, run, or repeated correction.
- **Exact location**: where the change belongs, or why a new skill is justified.
- **Exact text**: a small diff, append block, or complete tiny `SKILL.md`.
- **Expected benefit**: what next similar task becomes smoother or safer.
- **Verification**: at least one command or manual check after applying.

Reject outputs that only summarize history without proposing a minimal action,
or that propose action without evidence.
