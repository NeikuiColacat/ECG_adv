训练态总数据流

主线范式

主方法不是输入端修复器，也不是 operator oracle。训练时仍然保留 ECGTwin VAE latent-hull hard-sample search + online adversarial training + locked three-chain AugMix。模型通过训练参数吸收困难样本，而不是在评估时加额外前处理模块。

1
PTB-XL source training + PN2021 K500 full fine-tuning
模型先具备 PTB-XL Super5 任务能力，再用每个目标中心 K=500 条 PN2021 target ECG 做全量微调。K500 样本在最终 PN2021/PN2021-C 评估中 ref-excluded。
↓
2
K500 target anchors 进入 ECGTwin VAE latent space
ECGTwin VAE 输入输出是 (B, 1024, 12) channels-last raw mV；latent 是 (B, 4, 128)。解码后需要转成 PTB-XL lead order，并重采样到模型需要的长度。
↓
3
Latent-Hull 线性组合困难样本搜索
在同标签/兼容标签邻域内做 ECGTwin VAE latent 线性组合；如果使用梯度信号，也是在 latent-hull 约束内调整组合权重或选择更难的组合，不是在原始 ECG 输入空间做普通 PGD 扰动。目标是得到让当前分类器更难的 on-manifold ECG 变体。
↓
4
Locked three-chain AugMix
保留三链路混合拓扑，不退化为单链路。当前 cand94 的 per_op + depth=1 版本中，每个 copy 的两条 raw chain 都是单算子污染视图，第三条是 VAE-LH adversarial waveform chain；三路加权混合后再进入 BCE/JSD 训练约束。
↓
5
模型参数更新
EffNet 和 ECGFounder 都是通过 full fine-tuning 或对齐的 fullFT 训练路线把这些困难样本吸收到模型参数里；不把 stabilizer35、raw-supervised 独立分支、operator oracle 算作当前主方法。

VAE-LH + AugMix 训练细节

per-op 调度的准确含义

当前 EffNet cand94 和 ECGFounder aligned 版都用了 op_schedule=per_op 且 depth=1。代码里每个 copy 使用 ops[copy_i % len(ops)] 选择算子；因为 depth=1，一条 raw chain 内不会出现 baseline_wander -> emg_noise -> masking 这种串联复合算子。复合性来自两条 raw corruption chain 与一条 VAE-LH adversarial waveform chain 的三路混合，以及多个 copy 覆盖不同算子。

Clean 与 Corrupted 的评估规则

Clean path

Clean 不是随便拿旧 JSON 对比。每个模型都要按同一个输入模式重算 clean metric。比如 ECGFounder 的 bottleneck5000 clean 是 raw ECG 到 100Hz/1000、插值到 500Hz/5000、global z-score 后进模型；powerline 的 native_raw_first clean 也要对应同一路径重算。

这样计算的 drop 才是同一路径 clean 和 corrupted 的差值，避免把不同插值/z-score 链路混在一起。

Corrupted path

PN2021-C 报告使用单算子评估，不把 AugMix 混合视图当作测试集。每个 center 分别跑五个算子，最后聚合为四中心 × 五算子的 mean AUROC / AUPRC。

训练中的 AugMix 是用来提升模型鲁棒性的训练机制；评估中的 PN2021-C 是固定 stress benchmark，用来衡量模型是否在腐蚀 ECG 上恢复性能。

旧版 preprocessed cache 为什么不等价

旧版低 drop 的关键原因

历史 ECGFounder 默认 preprocessed_cache 不是 raw-first 污染。它会加载已经 per-sample z-score 的 100Hz/1000 clean cache，在这个标准化坐标系里加 corruption，然后 ECGFounder 输入转换还会再次 global z-score。对 baseline_shift 这类近似直流偏移，后面的 z-score 会消掉整体均值平移成分，所以旧版 drop 不能直接和当前 raw-ish/bottleneck waveform corruption 比。

口径 数据流 主要问题
historical preprocessed_cache 100Hz/1000 z-scored cache -> corruption -> 1000 to 5000 + global z-score -> model 污染发生在已经标准化的输入缓存上，而且污染后还有一次 z-score；baseline 类算子有效强度会被压弱。
current raw_first raw ECG -> 100Hz/1000 no z-score -> corruption -> global z-score -> model 更接近模型收到污染 ECG 后再做输入归一化的流程，适合 EffNet 非 powerline。
current bottleneck5000 raw ECG -> 100Hz/1000 no z-score -> 500Hz/5000 no z-score -> corruption -> global z-score -> ECGFounder 对齐 ECGFounder 输入长度；非 powerline 在 ECGFounder 5000 点 waveform 上注入。
current native_raw_first raw native fs/native length -> corruption -> model-specific preprocessing -> model 用于 powerline，因为工频污染最好模拟采集端污染，而不是在 100Hz Nyquist 附近硬加。

答辩用一句话版本

EffNet 和 ECGFounder 都使用同一个 PN2021-C stress profile，但由于模型输入长度不同，非 powerline 算子的注入点分别是 EffNet 的 100Hz/1000 raw-ish waveform 和 ECGFounder 的 500Hz/5000 bottleneck waveform；powerline 则统一在 native raw 采集端注入。我们的主方法通过 VAE latent-hull 搜索困难样本，并把 hard waveform chain 融入 locked three-chain AugMix 训练，让鲁棒性来自模型参数学习，而不是评估时额外前处理。
