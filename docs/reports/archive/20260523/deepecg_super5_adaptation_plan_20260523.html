DeepECG 适配 Super5 与 VAE-only Latent-Hull 方案

目标：把 DeepECG 的原生 77 类模型，尤其是 WCR Transformer，接入我们当前 PTB-XL Super5、 PN2021 跨中心评估、ECGTwin VAE latent-hull 在线对抗训练闭环。

日期：2026-05-23 DeepECG 输入：250Hz × 10s = 2500 点 Super5 head：我们自己训练 推荐首测：frozen WCR encoder + Linear(768,5)

结论先行

可以 100Hz 可以插值到 250Hz

为了满足 DeepECG 输入协议，可以把 100Hz/1000点 临时重采样到 250Hz/2500点。

但 插值不会恢复高频信息

从 100Hz 插值到 250Hz 只是满足长度和接口要求，不会恢复 100Hz 采样时已经丢失的高频。

推荐 raw cache 与 VAE path 分开

真实 PTB-XL/PN2021 建 DeepECG feature cache 时优先从 raw WFDB 直接重采样到 250Hz；VAE decoded 样本只能插值。

适配原则：不要把整个项目主线改成 250Hz。EfficientNet1DV2、PN2021 clean cache、ECGTwin VAE latent 仍保留当前协议； 只有进入 DeepECG 模型前，通过专用 adapter 转成 (B,12,2500)。

DeepECG 两条模型线

模型 参数量 类型 原生输出 Super5 适配建议
DeepECG EfficientNetV2 77类 JIT 约 1.51M CNN 77 个 ECG pattern 概率/logits 快速 smoke 可用 77 -> 5 adapter；论文主比较不优先。
DeepECG WCR 77类 约 90.43M Transformer 77 个 ECG pattern logits，encoder dim 768 推荐冻结 encoder，训练 Linear(768,5) Super5 head。
DeepECG WCR base_ssl 约 90.88M Transformer SSL 底座 预训练表示 可作为后续 full fine-tune 起点，不作为第一轮主线。
不建议把 77 类原生输出直接手工映射成 Super5 作为最终比较。更公平的是像 ECGFounder 一样： 冻结预训练表示，然后用 PTB-XL fold 1-8 训练我们自己的 5 类 Super5 head。

输入 adapter 怎么做

DeepECG 适配层只做模型入口转换，不改变原始训练/评估缓存的全局协议。

来源 输入现状 DeepECG adapter 适用场景
PTB-XL / PN2021 raw WFDB 原始采样率不一，通常可读物理单位。 读取 10s、lead reorder、直接重采样到 2500 点、z-score/DeepECG scale。 最严谨，适合建 frozen WCR feature cache。
现有 100Hz/1000 cache (B,1000,12) 或 (B,12,1000) 转 (B,12,1000) 后 F.interpolate(..., size=2500)。 快速 smoke、在线训练兼容；不恢复高频。
ECGTwin VAE decoded (B,1024,12)，ECGTwin lead order。 转置到 (B,12,1024)，lead reorder 到 PTB-XL，再插值到 2500。 VAE-only Latent-Hull 必需路径，可微。
AugMix / PN2021-C corruption 当前按 100Hz/1000 z-score 标定。 先在 100Hz canonical 上腐蚀，再送 DeepECG adapter 到 2500。 避免直接在 250Hz/500Hz 下误用 severity。

PyTorch 可微 adapter

def to_deepecg_2500(x_bct):
    # x_bct: (B, 12, L), PTB-XL lead order, 10s
    x_2500 = torch.nn.functional.interpolate(
        x_bct, size=2500, mode="linear", align_corners=True
    )
    return x_2500.float()
在线 Latent-Hull 必须用 PyTorch 可微路径。离线 feature cache 则可以用更高质量的 scipy.signal.resample_poly 或现有 resample helper。

Super5 适配路线

路线 做法 优点 风险 优先级
A. 77 logits -> Super5 adapter 冻结 DeepECG 原模型，训练 Linear(77,5)。 最快，工程量小。 受原生 77 类 head 限制，不是真正 representation probe。 快速 smoke
B. WCR encoder feature -> Super5 head 取 WCR encoder pooled 768-d feature，训练 Linear(768,5)。 最接近 ECGFounder frozen encoder 方案，公平可解释。 需要补 feature extractor wrapper，WCR 加载较重。 第一主线
C. WCR residual adapter 冻结 base Super5 head，加零初始化 MLP residual adapter。 适合 K=500 target-center adaptation。 需要控制 source performance，不然会过拟合 target。 第二阶段
D. full fine-tune WCR 解冻部分或全部 WCR。 上限可能最高。 90M Transformer，算力/过拟合/复现成本高。 最后再做

推荐实现路径

1. WCR smoke确认本地权重能 forward (B,12,2500)
2. feature cachePTB-XL / PN2021 raw -> 250Hz -> 768 feature
3. Super5 headfold 1-8 train, fold 9 select, fold 10 test
4. K=500 realtarget real head/adaptor fine-tune
5. VAE LHATlatent -> decode -> 2500 -> WCR -> Super5 logits

阶段 1：只做 frozen WCR Super5 baseline

  1. 新增 DeepECGWCRFeatureExtractor，路径不要依赖 ./fairseq-signals 当前工作目录。
  2. 从 raw WFDB 建 ptbxl_wcr_features.npz 和 pn2021_wcr_features.npz。
  3. 训练 Linear(768,5)，使用 PTB-XL fold 1-8，fold 9 按 macro AUPRC 选 best。
  4. 评估 fold10 与 PN2021 ref-excluded views。

阶段 2：K=500 real-only 与 VAE-only 对比

实验组 训练内容 回答的问题
WCR baseline PTB-XL Super5 head only。 DeepECG WCR 的跨中心起点有多强。
WCR + K500 real target-center 500 条真实样本微调 head/adapter。 增益是否主要来自目标中心真实数据。
WCR + VAE LHAT target real anchors + same-label latent-hull 在线 AT。 VAE latent manifold 是否在 WCR 上提供额外收益。
WCR + K500 real + AugMix JSD 只对 source/target real 做 corruption consistency。 采集噪声增强与 target adaptation 是否互补。

VAE-only Latent-Hull 接入细节

为了让 PGD 能从 Super5 loss 回传到 ECGTwin latent，DeepECG WCR 路线需要一个可微 victim wrapper。

z: (B, 4, 128)
  -> ECGTwin decoder, out-of-place scale
  -> ecg: (B, 1024, 12)
  -> transpose/reorder: (B, 12, 1024)
  -> interpolate to 2500
  -> WCR encoder / Super5 head
  -> logits5
  -> BCE loss for latent-hull PGD
可行点

F.interpolate 是可微的，能支持 latent-hull 内层优化；冻结 WCR 参数时仍可对输入求梯度。

风险点

现有 WCR classification wrapper 返回 77 类 sigmoid，不等于 Super5 logits。要新写 raw 5-logit wrapper，不要拿 sigmoid 后概率做 BCE 内层攻击。

DeepECG 与现有主线的预处理边界

分支 保留协议 不要做的事
EfficientNet1DV2 Super5 主线 100Hz/1000点，minimal_resample，per-sample global z-score。 不要为了 DeepECG 把主线 cache 全部重建成 250Hz。
ECGTwin VAE latent VAE latent (4,128)，decode 后 1024点，再按目标模型 adapter 转换。 不要在 latent 上做二次 z-score；不要破坏 lead order swap 规则。
DeepECG EfficientNet / WCR 进入模型前统一 (B,12,2500)。 不要把 77 类原生 head 当成我们的 5 类 head。
AugMix / PN2021-C 当前 severity 按 100Hz/1000点 标定。 不要未经重标定直接在 250Hz 或 500Hz 上套同一 severity。

建议先跑的 smoke tests

  1. 加载 WCR 权重，在 GPU 上 forward 随机 (2,12,2500)，确认输出 (2,77)。
  2. 用 8 条 PTB-XL raw ECG 建 2500 输入，确认无 NaN/Inf、shape 正确、速度可接受。
  3. 提取 128 条 PTB-XL WCR 768-d feature，训练一个 tiny Linear(768,5) overfit smoke。
  4. 用一个 VAE latent decode 后插值到 2500，跑 WCR Super5 logits，并测试 loss.backward() 能回到 latent。
  5. 只跑一个中心、一个 epoch 的 K500 real-only 和 LHAT smoke，确认显存和时间。

最终判断口径

如果 DeepECG WCR baseline 已经比 EfficientNet1DV2 强，再看 VAE-only 是否还能在 K500 real-only 之上增加 AUPRC。 只有 WCR + VAE LHAT 明确超过 WCR + K500 real，才能说 VAE latent-hull 在 DeepECG 表示空间上仍有独立价值。
如果两者打平，结论应写成：DeepECG WCR 的跨中心增益主要来自 foundation representation 与少量 target real adaptation； VAE-only Latent-Hull 对 WCR 的额外增益不稳定，但仍可作为 EfficientNet1DV2 上更有效的低资源增强策略。
