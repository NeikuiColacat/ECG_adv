核心结论

建议引入 YAML 配置管理，而且应作为当前项目重构的第一批落地事项之一。目标不是让配置“看起来整齐”，而是让每个论文结果都能被 tracked config、local config、resolved run config 和 manifest 追溯。

痛点 长 bash 易漏参

当前实验依赖大量命令行参数，mapping、K500、ref exclusion、selector、drop-all-zero view 等任一参数漏传都会让结果不可比。

方案 YAML 管实验定义

把论文实验定义放到 Git 跟踪的 YAML；把本机路径放到 local YAML；每次运行写出 resolved config。

边界 Bash 只负责启动

Bash 只保留 GPU、config、local-config、run-id、dry-run/resume/force，不再承担方法定义。

最容易出错的参数

  • PN2021 Super5 mapping 版本是否一致。
  • K=500 target-center ref ids 是否被正确 exclude。
  • direct fine-tune 和 VAE online AT 是否使用同一批 K500。
  • final selector 是否只使用 K500 internal validation 和 source floor。
  • all-zero kept 和 drop-all-zero 指标是否被混算。
  • 旧机器 /root/autodl-tmp 路径是否被误用。

设计原则

配置层 保存内容 是否进 Git 说明
Experiment YAML backbone、mapping、K-shot、centers、preprocess、training、VAE/PGD、selection、eval views、seeds。 是 这是论文实验定义，必须可审查、可复现。
Local YAML data root、model root、output root、python env、cache root、共享服务器资源偏好。 否 这是机器环境，不应污染 Git，也不应写死在实验 YAML。
CLI Override run-id、dry-run、resume、force、output-dir 等少量字段。 命令记录进 manifest 只允许白名单 override，防止重新变成长 bash。
Resolved Config 合并所有层后的完整配置。 随 run artifact 保存 以后复现和审稿只看 resolved config，不猜当时怎么启动。

推荐启动命令

micromamba run -n ECGTwin python scripts/run_experiment.py \
  --config configs/experiments/effnet_vae_lhat_k500_v6.yaml \
  --local-config configs/local/linbinhao_server.yaml \
  --run-id effnet_vae_lhat_v6_k500_seed20260531_20260527 \
  --dry-run

正式运行时先运行 nvidia-smi，确认目标 GPU 空闲，再显式设置 CUDA_VISIBLE_DEVICES=... 并使用 --execute。GPU 选择留在命令行环境变量，不写进 tracked YAML。

配置合并优先级

  1. code defaults：只放极少量安全默认值。
  2. configs/defaults/*.yaml：模型/方法默认参数。
  3. configs/experiments/*.yaml：论文实验定义。
  4. configs/local/*.yaml：本机路径和资源。
  5. CLI override：只允许 run_id、resume、dry_run 等少量字段。

实现路线

Phase 0：文档与 schema 冻结

新增 configs/README.md、schema、local example 和 local gitignore。不改训练逻辑、不启动 GPU。

Phase 1：path resolver 与 config loader

新增 util/project_paths.py 或未来 ecg_adv_gen/paths.py，实现路径解析、home-boundary 校验和 dry-run。

Phase 2：先包三条主线

优先覆盖 effnet_direct_k500_v6、effnet_vae_lhat_k500_v6、ecgfounder_inithead_fullft_k500_v6。当前已落地：VAE-LHAT 显式使用 direct-K500 checkpoint 和 compatsoft direct-init 参数；run_manifest.json 已加入 artifact_trace，记录 K500 ref-meta、frozen k500_ref_ids.json、anchors、init checkpoint/head、child output root 和 expected eval JSON；generated legacy commands 会经过协议审计，--execute 前会验证 required inputs，返回 0 后还会验证 launch/child artifacts 和 eval JSON mapping metadata。

Phase 3：统一 metrics exporter

从现有 JSON/CSV 回填 metrics_long.csv 和 artifact_manifest.json，不用重跑实验。当前 exporter 已同时写入 raw view 与 canonical_view，paper table exporter 按 canonical view 汇总并保留 raw_views，避免 ECGFounder target view 与 PN2021 ref-excluded view 口径漂移。

Phase 4：逐步抽库包

在 wrapper 稳定后，再抽 ecg_adv_gen.labels、ecg_adv_gen.ecg、ecg_adv_gen.data、ecg_adv_gen.models、ecg_adv_gen.training、ecg_adv_gen.adaptation、ecg_adv_gen.reporting。

第一版 run_experiment.py 不需要真的训练，只要能解析 YAML、校验路径、输出旧脚本命令、resolved config 和 manifest artifact trace，就已经能显著降低后续实验出错概率。当前 CPU-only refactor 测试为 53 passed。

必须防止的错误

不要提交 本机 local YAML

configs/local/*.yaml 真实文件必须 gitignore，只提交 *.example.yaml。

不要写死 GPU id

GPU 选择用 CUDA_VISIBLE_DEVICES，不要进入 tracked experiment YAML。

不要依赖 绝对路径

tracked YAML 不应依赖 /home/linbinhao 或 /root。路径通过 local YAML 或环境变量解析。

不要混算 v3/v5/v6

exporter 必须拒绝混用不同 PN2021 mapping 版本的结果。

不要只存 原始 YAML

每次 run 必须保存展开后的 resolved config，否则后续仍然无法复现。

不要先搬 大脚本

先 wrapper、manifest、metrics，再拆 synth_online_at_super5.py 和 ECGFounder runner。

推荐下一步

建议下一轮直接落地 Phase 0 + Phase 1 的骨架。第一版只做 dry-run，不启动 GPU，不改训练逻辑。
  1. 新建 configs/README.md。

  4. 新建 configs/experiments/effnet_direct_k500_v6.yaml。
