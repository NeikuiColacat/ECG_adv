一句话总结

当前可信主线不是“直接生成一批 ECG 加进去训练”，而是： 先用 PTB-XL Super5 训练好的 EfficientNet1DV2 作为源模型，再用每个 PN2021 目标中心固定 K=500 条带标签真实 ECG 做直接微调， 最后把同一批目标中心真实 ECG 编码进 ECGTwin VAE latent space，在同标签或标签兼容的局部 latent hull 内在线寻找对当前分类器有压力的 on-manifold 对抗样本，并与真实 K500 anchor 一起继续训练。

当前主张：VAE-LHAT 在 Direct K500 之上提供额外增益，而不是把 K500 目标中心监督微调的全部增益都归功于 VAE。

当前可信事实以 configs/active_evidence_registry.yaml 为准；旧 v3/v5/v6 报告只作为历史和敏感性分析上下文。

数据输入输出流动 Pipeline

1. PTB-XL 源模型 PTB-XL Super5 真实 ECG 训练 EfficientNet1DV2，得到 source checkpoint。
2. PN2021 标签投影 PN2021 SNOMED 标签经 v7 映射成 5 维 multi-hot。
3. K500 Anchor 每个目标中心固定抽 500 条，生成 signals / latents / ref_meta。
4. Direct K500 源 checkpoint 在 K500 上直接微调，得到公平对照。
5. VAE-LHAT Direct checkpoint 初始化，VAE latent hull 在线对抗训练。
6. Ref-excluded Eval PN2021 held-out ref-excluded，导出 metrics_long 和 comparison bundle。

主线方法技术细节

Direct K500 baseline

Direct 是必须保留的强对照：它从同一个 PTB-XL EfficientNet1DV2 source checkpoint 出发，只使用目标中心 K=500 真实 ECG 做 supervised fine-tuning， 不使用 ECGTwin、不使用 latent hull、不使用 synthetic/adv buffer。这样能回答一个关键问题：提升究竟来自 K500 目标中心标签，还是 VAE 在线对抗训练。

当前 Direct 训练入口是 scripts/paper/run_direct_finetune_k500_20260516.py， YAML 包装是 configs/experiments/effnet_direct_k500_v7_sjr_rgq.yaml。

VAE Latent-Hull Online AT

VAE-LHAT 从每个中心的 Direct K500 checkpoint 初始化。每轮从目标中心 K500 real anchors 中采样，取其 ECGTwin VAE latent z0，在同标签或标签兼容的候选 latent 集合里构造局部 convex hull： 

z_mix = sum_i softmax(a_i) * z_i
z_adv = (1 - lambda) * z0 + lambda * z_mix

只优化 mixture logits a_i，不做任意自由 latent 噪声扩张。当前默认设置偏保守： M=20 lambda=0.05 steps=3 lr=0.25 include anchor standardized latent distance local_random neighbor

训练损失同时看 clean K500 anchors、VAE adversarial decoded samples、以及 source floor 约束。当前目标是让攻击成功率落在约 30%-70% 的有用压力区间，而不是单纯追求攻击越强越好。

Latent AugMix branch 的位置

当前 v7 VAE 配置走的是 stage-3 wrapper： scripts/paper/run_effnet_latent_augmix_stage3_20260524.py。 它把 VAE latent-hull adversarial decode 作为 AugMix 风格增强中的一个 latent branch，并与 ECG 信号增强链路组合。

当前默认： width=3 depth=-1 alpha=1.0 severity=2 latent_weight_cap=0.25

这部分最需要人工确认：论文主张应写成“VAE on-manifold adversarial regularizer + AugMix-style branch”，不要写成 ECGTwin DiT 直接合成样本带来主要增益。

标签与选择策略

标签映射代码源是 scripts/triple_labels/label_schemes.py； 稳定 metadata 在 ecg_adv_gen/labels/super5.py。 当前 v7 映射来自 SJR/RGQ 医生审核方案，mapping hash 为 555ec85d5b51。

方法开发阶段可以观察 held-out 结果做方向判断，但最终可发表 recipe 不应该依赖完整目标中心类别分布、held-out test labels、或针对某个中心手动特调参数。 当前 registry 中记录的选择策略是 k500_internal_val_plus_source_floor。

审稿级人工检查问题

数据泄漏

PN2021 的 K500 ref ids 是否从最终目标中心 eval 中排除？ptb-xl/ptbxl shard 是否硬排除？

Direct 和 VAE 是否使用同一批 K500、同一个 seed、同一标签映射、同一评估 view？

方法归因

论文中是否明确 Direct K500 是强对照？VAE-LHAT 的 claim 是否只写“相对 Direct 的额外增益”？

是否避免把 ECGFounder 或 Direct full fine-tuning 的 gain 写成 VAE causal gain？

标签映射

v7 SJR/RGQ 医生审核映射是否完整同步到 label_schemes.py 和 super5.py？

节律类/病史类标签的 suppress-only / ignore 处理是否符合当前文档？

攻击强度

ASR 是否大致在 30%-70%？如果某中心过低或过高，是全局 recipe 现象还是中心特调造成的？

decoded invalid rate 是否低；hard rejection 是否只过滤非有限、flatline、严重幅度等物理异常？

预处理一致性

ECGTwin decode 后 1024 点是否正确转为 EfficientNet 的 1000 点、PTB-XL lead order、100 Hz？

PN2021 和 PTB-XL 是否都进入同一个 classifier contract：(N,1000,12) on disk，(B,12,1000) in model？

可复现证据

每次新 run 是否有 run_card.json、run_file_index.json、summary.md、run_manifest.json？

metrics 是否能从 eval JSON 一路追到 paper table 和 comparison delta？

最重要的论文风险：不要用完整目标中心测试集类别分布或 held-out 标签来挑 recipe；不要把 K500 直接微调带来的提升归因给 VAE； 不要混用 v6/v7 mapping 或 all-zero-kept/drop-all-zero view。
