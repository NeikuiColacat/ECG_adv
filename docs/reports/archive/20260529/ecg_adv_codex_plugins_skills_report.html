1. 执行摘要

对 ECG_adv 这种深度学习科研项目，最合适的 Codex 配置不是“安装一堆万能 skills”，而是采用：

Superpowers 做总控流程
GitHub MCP Server 做只读仓库上下文
Dimillian/Skills 做重构、review、bug hunt
DVC + MLflow/W&B 做数据与实验治理
repo-local skills + AGENTS.md 固化 ECG 项目规则
最终建议：先装 Superpowers，再配置只读 GitHub MCP；科研工程层面安装 DVC + 本地 MLflow； 只精选几个高价值第三方 skills；真正重要的 ECG 规则写进 AGENTS.md 和 .agents/skills/。
重要限制：公开侧没有确认到 NeikuiColacat/ECG_adv 仓库页面。本报告把公开可见的 NeikuiColacat/ECG-diffusion 作为邻近证据，并把 ECG_adv 视为私有或未公开 ECG 深度学习仓库来给出配置建议。

2. 仓库观察与工作假设

公开可见的 ECG-diffusion 是 Python 深度学习项目，包含 src/、tests/、 requirements.txt、setup.py 等结构。依赖中可见 numpy、pandas、 scikit-learn、tensorflow、matplotlib、seaborn、pytest。

它暴露出典型科研代码问题：入口脚本、配置对象、数据加载函数、测试用例与模型构造函数之间存在接口漂移。 因此，对 ECG_adv 的 Codex 配置应优先处理以下问题。

工程痛点

  • 训练入口、评估入口和预处理入口不稳定
  • 测试存在但可能过时，不能作为唯一安全兜底
  • 数据 split、标签映射、采样率、导联顺序容易被 agent 顺手改坏
  • checkpoint、数据缓存、实验日志不适合进入 Git

配置目标

  • 先分析，再修改
  • 多 agent 并行读，单 worker 小步写
  • 每个 work packet 都有验证命令
  • GitHub、MCP、实验平台默认保守权限

4. 从 ECG 项目需求映射到工具

需求 推荐工具 理由
安全探索私有仓库，不一上来改文件 Superpowers + GitHub MCP read-only 先规划、先读 repo/PR/CI，再决定是否修改
重构训练、数据、评估模块 orchestrate-batch-refactor 先依赖分析，再拆 work packets，避免多个 agent 同时写同一文件
训练失败、NaN、shape mismatch、checkpoint 问题 bug-hunt-swarm + 本地 training-debugger 并行只读调查，先找最小复现路径
提交前审查 diff review-swarm 多路只读 review，关注行为回归、可靠性、测试缺口
数据、checkpoint、缓存不能进 Git DVC 把数据和模型版本从 Git 中分离出去
实验可追踪、可比较、可复现 MLflow，本地优先；W&B 条件启用 记录参数、指标、模型、环境和运行元数据

5. 建议的 Codex 配置

项目级配置可以放在 ECG_adv/.codex/config.toml。建议保守写权限、只读 GitHub 上下文、有限 subagent 并发。

.codex/config.toml

model = "gpt-5.5"
approval_policy = "on-request"
sandbox_mode = "workspace-write"
web_search = "cached"
model_reasoning_effort = "high"

[agents]
max_threads = 4
max_depth = 1

# Docker 方式接入 GitHub MCP Server，默认只读
[mcp_servers.github]
command = "docker"
args = [
  "run", "-i", "--rm",
  "-e", "GITHUB_PERSONAL_ACCESS_TOKEN",
  "-e", "GITHUB_TOOLSETS=repos,issues,pull_requests,actions",
  "-e", "GITHUB_READ_ONLY=1",
  "ghcr.io/github/github-mcp-server"
]
env_vars = ["GITHUB_PERSONAL_ACCESS_TOKEN"]
startup_timeout_sec = 20
tool_timeout_sec = 60
required = false
default_tools_approval_mode = "prompt"

不用 Docker 时的 GitHub MCP 配置

[mcp_servers.github]
command = "/Users/you/.local/bin/github-mcp-server"
args = ["stdio", "--read-only", "--toolsets", "repos,issues,pull_requests,actions"]
env_vars = ["GITHUB_PERSONAL_ACCESS_TOKEN"]
startup_timeout_sec = 20
tool_timeout_sec = 60
required = false
建议：GitHub token 放在用户本地环境变量里，不要写入 repo 级配置文件。

6. 自定义 Subagents

对 ECG_adv，建议只加三个项目定制 agent：repo_mapper、reviewer、training_debugger。 重点是让它们分工明确，尤其是 reviewer 保持只读。

.codex/agents/repo-mapper.toml

name = "repo_mapper"
description = "Read-only explorer for ECG_adv. Map entry points, training flow, data pipeline, and validation commands before any edits."
model = "gpt-5.4-mini"
model_reasoning_effort = "medium"
sandbox_mode = "read-only"

developer_instructions = """
Stay in exploration mode.
Identify the real training/evaluation/data-prep entry points.
Return concrete file paths, commands, and coupling risks.
Do not edit files.
"""

.codex/agents/reviewer.toml

name = "reviewer"
description = "Read-only reviewer for behavior regressions, data-prep drift, evaluation drift, and missing tests."
model = "gpt-5.4"
model_reasoning_effort = "high"
sandbox_mode = "read-only"

developer_instructions = """
Review like a code owner of an ECG ML project.
Prioritize correctness, split leakage risk, preprocessing drift, metric drift, reproducibility, and missing test coverage.
Avoid style-only comments.
"""

.codex/agents/training-debugger.toml

name = "training_debugger"
description = "Read-heavy training failure investigator for ECG_adv."
model = "gpt-5.4"
model_reasoning_effort = "high"
sandbox_mode = "workspace-write"

developer_instructions = """
First diagnose, then patch only if asked.
Focus on data loader shape issues, NaN/Inf, config drift, metric drift, checkpoint path mistakes, and train/eval mismatch.
Prefer the smallest reproducible command.
"""

7. AGENTS.md 模板

AGENTS.md 应该写项目不变量，而不是一次性技巧。ECG 项目最重要的是数据处理、split、标签映射、评估口径和 artifact 纪律。 

# ECG_adv Agent Rules

## Repo invariants

- Do not change train/val/test split logic unless the user explicitly asks.
- Do not change ECG lead order, sampling-rate assumptions, label mapping, or normalization conventions without calling it out.
- Treat data preprocessing, evaluation metrics, and checkpoint naming as behavior-critical.
- Prefer behavior-preserving refactors over architectural rewrites.

## Data and artifact handling

- Never commit raw ECG data, preprocessed waveforms, checkpoints, mlruns/, wandb/, .dvc/cache/, or large artifacts to Git.
- Track datasets, checkpoints, and derived artifacts with DVC when possible.
- Never print or export patient metadata unless the user explicitly asks.

## Validation gates

- Before editing, find the narrowest real validation command.
- After any change to data/preprocessing/training/evaluation code, run at least one smoke validation.
- If tests are obviously stale, say so explicitly and do not overclaim safety.

## Workflow

- Analyze first, edit second.
- One work packet at a time.
- No parallel writes to overlapping files.
- Reviewer remains read-only.

safe-refactor-dl/SKILL.md

---
name: safe-refactor-dl
description: Refactor ECG_adv data, training, and evaluation code with strict behavior preservation, packetized changes, and mandatory validation.
---

# Safe Refactor DL

## Non-negotiables

- Do not change data split logic, label mapping, lead order, sampling rate assumptions, or metric definitions unless explicitly requested.
- Prefer behavior-preserving refactors.
- Do not parallel-edit overlapping files.
- Treat preprocessing and evaluation as contract-critical.

## Workflow

1. Map the true entry points and validation commands.
2. Produce a small refactor plan before editing.
3. Split the work into packets with owned files and checks.
4. Edit one packet at a time.
5. Run the smallest relevant validation after each packet.
6. Summarize invariants preserved and residual risks.

## Validation order

1. Targeted smoke test
2. Touched-module tests
3. Broader repo checks if packet crosses module boundaries

## Stop conditions

- Tests are stale or misleading
- Refactor requires changing metrics/splits/preprocessing semantics
- Multiple packets collide on file ownership

training-debugger/SKILL.md

---
name: training-debugger
description: Diagnose ECG_adv training failures, regressions, NaNs, shape mismatches, checkpoint issues, and train/eval drift.
---

# Training Debugger

1. Capture the exact failing command and environment.
2. Identify whether the seam is data, config, model, optimizer, metric, or checkpoint.
3. Prefer the smallest reproducible command.
4. Report likely root cause, missing evidence, and fastest proof step.
5. Do not rewrite training code unless explicitly asked.

reproducibility-check/SKILL.md

---
name: reproducibility-check
description: Verify that ECG_adv experiments are reproducible and traceable.
---

# Reproducibility Check

1. Check seed control and split determinism.
2. Check whether params/config are fully logged.
3. Check artifact lineage: dataset -> preprocess output -> checkpoint -> metrics.
4. Check whether the exact evaluation command can be replayed.
5. Flag missing version info, environment drift, and unnamed artifacts.

data-prep-validator/SKILL.md

---
name: data-prep-validator
description: Validate ECG data loading, preprocessing, split integrity, and label-map contracts.
---

# Data Prep Validator

1. Verify input schema and expected columns/files.
2. Verify split rules and leak guards.
3. Verify sampling-rate assumptions, lead order, normalization, and filtering.
4. Verify output shape and label mapping contract.
5. Require a tiny fixture or smoke command before approving changes.

model-eval/SKILL.md

---
name: model-eval
description: Standardize ECG_adv evaluation commands, metric naming, output reports, and comparison tables.
---

# Model Eval

1. Find canonical evaluation entrypoint.
2. Confirm metrics and aggregation rules.
3. Run or specify the smallest valid eval command.
4. Write outputs to a standard location.
5. Summarize deltas against baseline with caveats.

experiment-runbook/SKILL.md

---
name: experiment-runbook
description: Plan ECG_adv experiments, ablations, seeds, metrics, artifacts, and tracking conventions.
---

# Experiment Runbook

1. Define baseline, hypothesis, variable changed, and expected metric movement.
2. Specify dataset version, split version, config path, seed list, and GPU budget.
3. Record MLflow or W&B logging fields.
4. Define checkpoint naming and artifact storage.
5. Produce a result table skeleton before running large experiments.

9. 分阶段安装与迁移计划

D0–D1
核实真实仓库结构。拉出 ECG_adv 文件树、训练入口、评估入口、数据预处理入口、测试命令、CI 配置。
D1–D2
安装 Superpowers。在 Codex CLI 中执行 /plugins，搜索 superpowers 并安装。
D2–D3
接入只读 GitHub MCP。只启用 repos,issues,pull_requests,actions，并强制 read-only。
D3–D4
建立 DVC + MLflow 基线。数据、checkpoint、预处理产物走 DVC；实验参数和指标先走本地 MLflow。
D4–D5
写 AGENTS.md 与 repo-local skills。先写 safe-refactor-dl、training-debugger、reproducibility-check。
D5–D7
加项目定制 subagents。跑一次只读 dry-run，确认能稳定执行“先分析、后修改、再复核”。

10. 安全边界

核心原则：把第三方 MCP server 当成本机会执行的程序，默认零信任；把医学/ECG 数据当作敏感数据，默认不外发。
  • GitHub MCP 默认 read-only，不要暴露 all toolsets。
  • GitHub token、W&B API key、云存储密钥只放本地环境变量，不写入 repo。
  • 禁止把 raw ECG、预处理波形、checkpoint、mlruns/、wandb/、.dvc/cache/ 提交到 Git。
  • 未明确授权时，不允许 agent 自动上传 artifacts 到外部服务。
  • 任何改动 split、label map、sampling rate、lead order、normalization、metric 的操作都必须单独说明。
  • W&B 仅在团队允许云端同步时启用；默认使用本地 MLflow。
