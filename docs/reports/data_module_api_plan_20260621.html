数据模块彻底重构需求分析

这版只做需求分析，不写业务实现。目标是从数据流动 pipeline 重新定义模块边界：每一步先讲清楚要解决什么问题，再给出 API 形状、输入输出、内存策略和验收点。设计默认利用 250G 内存提速，同时保留小内存机器可运行的 mmap/stream fallback。

重构目标

丢掉技术债

不再以 legacy 脚本为设计中心。脚本只做 CLI wrapper，数据真相由 package API 表达。

按数据流而不是文件名设计

从 raw dataset、manifest、cache、split、anchor、model view、eval view 到 report lineage，一步一步定义。

内存能力成为一等公民

默认 250G memory-first：可把核心数组常驻内存；小机器自动降级到 mmap 或 stream。

非目标

  • 本轮不改 Python 业务代码，不移动入口，不重写训练脚本。
  • 本轮不重新实现 ECGTwin decoder、PGD、AugMix 算子或模型训练循环。
  • 本轮不承诺完全兼容所有历史实验；需求分析会把 legacy 兼容作为独立边界，而不是让它污染新 API。
  • 本轮不把 500Hz ECGFounder cache 作为数据真相；它只是从 raw1000 派生出来的 model view。

硬契约

契约 固定值 需求含义
Super5 class order CD,HYP,MI,NORM,STTC 所有 label、logit、class weight、metric、anchor quota 都按这一顺序解释。
Classifier canonical waveform (N,1000,12), 100Hz, PTB-XL lead order 所有 source、target、decoded、eval clean cache 的统一波形中间层。
Torch model view (N,12,L) 模型输入是派生 view，不是 cache 真相。EffNet 用 1000，ECGFounder 用 5000。
ECGTwin latent (N,4,128), scale metadata required VAE-LHAT 只吃 latent pool，不直接解释文件路径和 label order。
ECGTwin decode 1024 -> reorder aVL/aVF -> 1000 decoded waveform 必须转成 PTB-XL lead order 和 100Hz/1000，再进入上层。
PN2021 eval full cache first, ref exclusion later K500 ref id 只在 eval view 阶段排除，不能烧进 full center cache。

250G 内存利用策略

新数据模块应该明确支持三种 load mode，并在当前机器默认使用 auto。auto 会估算数组大小和可用内存：小于预算时常驻内存，大于预算时使用 mmap，再大或随机访问不友好时使用 stream/shard。 

@dataclass(frozen=True)
class MemoryPolicy:
    mode: Literal["auto", "ram", "mmap", "stream"]
    ram_budget_gb: float = 180.0
    keep_source_ptbxl: bool = True
    keep_target_k500: bool = True
    keep_pn2021_eval_cache: bool = True
    prefer_float32: bool = True
    allow_object_arrays: bool = False
    mmap_fallback: bool = True

def estimate_array_gb(shape: tuple[int, ...], dtype: np.dtype) -> float: ...
def choose_load_mode(required_gb: float, policy: MemoryPolicy, available_gb: float) -> str: ...
RAM-first

PTB-XL、K500、常用 PN2021 clean eval cache 可以直接常驻内存，减少重复解压和磁盘随机读。

mmap fallback

PN2021 全中心或多版本 cache 过大时，使用 .npy mmap，避免一次性内存爆掉。

stream fallback

只在重新 materialize raw WFDB、超大腐败集、或小机器训练时使用。

显式 lineage

每个 cache 记录 load mode、shape、dtype、hash、mapping version，避免“看似复用，实际漂移”。

Pipeline 总览

下面每个 stage 都是一条需求。真正实现时可以一个 stage 一个 PR；但需求层面先完整画出来，避免重构到一半发现边界不对。

0 运行上下文与契约解析 config -> typed context

需求：所有数据 API 都必须从同一个上下文拿到 data root、output root、mapping version、class order、target/eval centers、preprocess contract 和 memory policy。不能让脚本各自读环境变量或各自拼路径。 

@dataclass(frozen=True)
class DataContext:
    data_root: Path
    output_root: Path
    source_dataset: Literal["ptbxl"]
    target_dataset: Literal["pn2021"]
    class_order: tuple[str, ...]
    mapping_version: str
    mapping_hash: str
    target_centers: tuple[str, ...]
    eval_centers: tuple[str, ...]
    preprocess: DataPreprocessContract
    memory: MemoryPolicy

def resolve_data_context(config: Mapping[str, Any]) -> DataContext: ...
def validate_data_context(ctx: DataContext) -> None: ...

验收：给定 YAML resolved config，可以构造唯一上下文；缺少 mapping hash、class order、leak-excluded center 时直接报错。

1 数据资产清单 paths -> inventory

需求：在真正加载数据前，先能快速知道 PTB-XL、PN2021、K500 artifact、latent pool、cache 是否存在、大小多少、会占多少内存。这是 250G 内存策略的入口。 

@dataclass(frozen=True)
class DataAsset:
    name: str
    path: Path
    kind: Literal["raw", "cache", "artifact", "manifest"]
    exists: bool
    size_gb: float | None
    expected_schema: str

@dataclass(frozen=True)
class DataInventory:
    assets: tuple[DataAsset, ...]
    total_existing_gb: float
    missing_required: tuple[str, ...]

def inspect_data_assets(ctx: DataContext) -> DataInventory: ...
def plan_cache_loads(inventory: DataInventory, policy: MemoryPolicy) -> dict[str, str]: ...

验收：只读运行，不能读大数组；能输出“哪些会 RAM-load，哪些会 mmap，哪些缺失”。

2 PTB-XL 元数据与标签 CSV/SCP -> labels/folds

需求：PTB-XL 的 label、fold、record id、row index 必须先独立成 manifest。波形是否加载是后面的事；标签和 split 不能和 waveform materialization 绑死。

    folds: np.ndarray           # (N,), int64

def load_ptbxl_manifest(csv_path: Path, *, ctx: DataContext) -> PTBXLManifest: ...
def split_ptbxl_manifest(manifest: PTBXLManifest, split_spec: SplitSpec) -> SplitIndices: ...

验收：fake CSV 可测；fold 1-8/9/10 默认稳定；Super5 order 和 mapping metadata 必须进入 metadata。

3 PTB-XL 波形存储 raw100.npy -> signal store

需求：PTB-XL source waveform 必须有统一 store。当前 250G 机器可以把 (N,1000,12) 直接常驻内存；小机器可以 mmap。训练代码不应该知道原始 cache 是 .npy 还是 RAM。

def load_or_build_ptbxl_signal_store(
    raw_path: Path,
    manifest: PTBXLManifest,
    *,
    ctx: DataContext,
    cache_path: Path,
) -> SignalStore: ...

验收：cache hit 不改变 shape/dtype；cache miss 的 preprocess contract 写入 metadata；不能偷偷 zscore 两次。

6 PN2021 Full Center Cache WFDB -> full clean cache

需求：PN2021 clean eval cache 必须是完整 center cache。这里只做读 WFDB、预处理、label mapping、写 cache；绝不做 K500 ref exclusion。

需求优先级

优先级 需求 原因
P0 DataContext, MemoryPolicy, hard contracts 没有上下文和契约，后面每个模块都会重新发明路径和 shape 规则。
P0 PTBXLManifest, SignalStore, ECGArrayDataset 这是最适合先做的 source pipeline，能快速减少 train_ptbxl.py 技术债。
P0 PN2021FullCenterCache, PN2021EvalView 这是指标安全边界，必须防止 ref exclusion/cache/metric view 漂移。
P1 KShotSelection, TargetAnchorPool 这是 VAE-LHAT / Direct-K500 / AugMix 主线的核心数据产品。
P1 ModelInputView, LatentBatch, AugMixInputBatch 让 EffNet、ECGFounder、VAE decode、AugMix 都从同一份 canonical waveform 派生。
P2 LegacyAdapter 只在新 API 稳定以后迁移旧入口，避免为了兼容历史脚本牺牲新设计。

第一步建议

真正开写代码时，第一步不是碰当前打开的 eval_crosscenter.py，而是先实现最底层的 DataContext、MemoryPolicy、PTBXLManifest、SignalStore、ECGArrayDataset。这部分能教清楚现代 Python 数据模块怎么设计，也不会碰 GPU 和主线实验。

第二步再处理 PN2021 full center cache 和 eval view，把 “full cache -> ref exclusion -> metric view” 这个安全边界钉死。等这两条 pipeline 稳了，再接 K500 anchor pool 和 VAE/AugMix。
