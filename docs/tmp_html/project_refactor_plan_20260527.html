结论摘要

当前项目不是“代码完全不能用”，而是已经进入论文冲刺阶段后，实验脚本、临时报告、路径默认值和结果归因混在一起。重构的第一目标不是把目录改漂亮，而是让每个论文 claim 都能被一个冻结 config、一个 run manifest、一个 mapping hash 和一组原始 JSON/CSV 追溯。

先别做 大规模搬目录

如果先重命名或移动脚本，最容易暗中改变标签映射、预处理、ref exclusion 和 checkpoint 选择规则，导致历史指标不可比。

先做 冻结事实链

先建立统一 config、manifest、metrics schema、path resolver 和 source-of-truth 文档，然后把旧脚本包成稳定入口。

最终状态 可复现、可迁移、可审稿

直接微调、VAE online AT、ECGFounder 对照都能用同一套 protocol 复跑和出表，且不会依赖旧机器绝对路径。

149 当前扫描到的 Python 脚本数，重构前需要分 active / historical / wrapper。
42 scripts/paper 下日期命名 runner 数量，很多是一次性实验编排。
49 docs/tmp_md 与 docs/tmp_html 中的临时报告数量。
v6 当前 PN2021 Super5 映射版本，历史 v3/v5 文档和文件名需要明确降级。

达成什么目的才算重构完毕

本项目的重构完成标准不应该是“目录看起来清爽”，而是下面五件事全部成立。

目的 1 论文结果可复现

每个主表数字都能追到：代码 commit、config、mapping version/hash、K500 ref ids、ref-exclusion、原始 eval JSON/CSV、selector 输出。

目的 2 方法归因清楚

EfficientNet1DV2 上 VAE Latent-Hull 的净增益、ECGFounder 上 target K500/fullFT/head init 的贡献边界要分开，不能混为一个“VAE 带来全部提升”。

目的 3 环境可迁移

无 /root/autodl-tmp、无 /root/miniforge3 的机器上，通过 CLI/env 仍能解析数据、模型、cache 和输出路径。

目的 4 主线入口稳定

direct K500、EfficientNet VAE online AT、ECGFounder 对照、PN2021 eval、PN2021-C eval 都有稳定入口；日期脚本只作为 wrapper 或 historical。

目的 5 不重复犯错

heavy quality gate、heldout-oracle selection、盲目加大 attack、selector-grid 空转、center-token 过度归因等都进入 decision log。

目的 6 共享服务器安全

所有写入默认在当前用户 home 下；GPU/长任务前检查资源；不提交大文件；不误删 v6 依赖的 v5 mmap cache 和外部模型。

目录关系建议

  • ecg_adv_gen/：可复用生产库，不能依赖 scripts.*。
  • scripts/：薄 CLI，调用 ecg_adv_gen.*，保留老命令兼容。
  • experiments/ 或继续 scripts/paper/：只做论文实验编排和 config wrapper。
  • configs/experiments/：主线 config，不再只靠 argparse 和日期脚本。
  • docs/final_paper/：当前 source of truth；docs/tmp_* 降级为过程记录。

低风险执行路线

Phase 0：冻结行为，不移动核心代码

建立 fixture 和 smoke test，锁住 class order、PN2021 v6 mapping hash、lead reorder、ECGTwin 1024->1000、ref exclusion、K500 split 和 metrics 口径。

目标：保证后续迁移时能发现任何隐式指标变化。

Phase 1：路径和配置层

新增 paths 工具和 config schema。路径优先级固定为 CLI 参数 > 环境变量 > 当前迁移 host 默认 > 报错。

环境变量：ECG_ADV_GEN_PROJECT_ROOT、ECG_ADV_GEN_DATA_ROOT、ECG_ADV_GEN_MODEL_ROOT、ECG_ADV_GEN_PYTHON。

Phase 2：manifest 与 metrics

每个 run 写 run_config.json、run_manifest.json、candidate_manifest.jsonl、metrics_long.csv。先从现有 JSON/CSV 回填，不急着重跑实验。

目标：论文表可以自动生成，且不会混用 v3/v5/v6 mapping。

Phase 3：抽最稳公共库

先抽 labels、ecg/preprocess、metrics、paths。旧文件 re-export 新模块，保持历史脚本可跑。

这是重构收益最大、风险最低的一步。

Phase 4：拆 online AT 主文件

把 synth_online_at_super5.py 拆成 latent pool、neighbor sampler、PGD attack、decode/preprocess、training stream、checkpoint selection、CLI 六层。

拆之前必须有 Phase 0 的行为测试，否则很难判断是否改坏。

Phase 5：统一 backbone adapter

EfficientNet1DV2、ECGFounder、DeepECG 都通过统一 adapter 暴露 input spec、feature/head、freeze/fullFT 策略、checkpoint I/O。

这样才能公平测试“同一套 VAE-only 方法在不同 backbone 上的表现”。

Phase 6：论文文档收口

把最新 closing summary 升格到 docs/final_paper/，旧 v3/v5、center-token、DiT synthetic、negative result 统一标注状态。

目标：后续 agent 不会把旧探索结果误当当前主线。

风险与禁区

禁区 先搬目录再补测试

这会让标签、预处理、cache、ref exclusion 变化混在一起，指标一旦变动无法定位。

禁区 混合 v3/v5/v6 结果

当前代码是 v6_super5_clinician_review_20260524；历史报告里的 v3/v5 必须标注为 historical 或 sensitivity。

高风险 提交外部模型 symlink

当前 model/DeepECG、model/ECGTwin 等是本机绝对路径 dirty symlink，不应随重构一起提交。

高风险 清理 v5 mmap cache

v6 PN2021 mmap cache 的 signals/record_ids 可能 symlink 到 v5，不能按文件名把 v5 当旧垃圾删除。

归因边界 ECGFounder

ECGFounder 的较大增益主要来自 K500 supervised adaptation、head init 和 fullFT recipe；VAE 是较小 refinement 或 selector diversity，不能过度声明。

方法边界 final selection

探索可看 held-out 反馈，但最终 protocol 不能根据完整目标中心测试分布或类别表现手调。

建议优先落地的最小重构

如果只做一轮最小重构，建议目标定为“让当前论文主线可复现并可追溯”，不追求一次性把全部历史代码整理干净。
  1. 新增 docs/final_paper/source_of_truth.md，把当前主线、证据路径、废弃路线和归因边界写清楚。
  2. 新增 configs/experiments/，先放三份主线 config：direct K500、EfficientNet VAE Latent-Hull、ECGFounder matched control。
  3. 新增 path resolver，先让新 wrapper 使用 ECG_ADV_GEN_DATA_ROOT，不急着全 repo 替换旧路径。
  4. 写 run_manifest 和 metrics_long exporter，从已有结果回填，不动 GPU。
  5. 给 scripts/paper 建 active index：哪些是 current-main，哪些是 ablation-only，哪些是 negative/historical。
  6. 把 docs/tmp_md/vae_online_at_closing_summary_20260525.md 升格为正式结果报告，HTML 报告只作为阅读版。
  7. 补 5 个 CPU/import-only 测试：mapping hash、lead reorder、1024->1000、ref exclusion、metrics_long 导出。

可交付时间估计

范围 预计时间 产物
最小可追溯重构 0.5-1 天 source-of-truth、active script index、config 草案、manifest/metrics schema、HTML/MD 报告。
主线可复现重构 2-4 天 三条主线 wrapper、path resolver、metrics exporter、CPU tests、旧结果回填。

推荐下一步：先做“最小可追溯重构”。这一步不会占 GPU，也不会动大数据，但能马上减少后续实验和写论文时的混乱。
