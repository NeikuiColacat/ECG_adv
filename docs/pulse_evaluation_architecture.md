# PULSE: code map and evaluation protocol

This branch studies native-500-Hz ECG images. The current comparison uses the
original PULSE-7B model and matched single-chain / three-chain rank32 adapters.
These are single-seed development results; they are not a paper-final claim.

## Read the implementation in this order

| Question | Owner |
| --- | --- |
| What will run, and where? | The selected `configs/experiments/pulse_full_lora32_*.yaml` and its referenced YAML closure |
| How are configs resolved and results sealed? | `boot_scripts/run_experiment.py`, `util/config_bundle.py`, `util/run_record.py` |
| Which model, records and training recipe are allowed? | `util/pulse_training_contract.py`, `core/pulse_finetune.py` |
| How are image-only single/three branches constructed? | `core/pulse_hybrid.py`, `core/image_augmix_gpu.py` |
| How does the shared inference backend switch adapters and decode tokens? | `util/evaluation/pulse_adapters.py` |
| How are cohorts, views, predictions and metrics paired? | `util/evaluation/pulse_hybrid_development.py` |
| What proves that a result is complete and reproducible? | `util/pulse_hybrid_contract.py` |
| Who schedules GPUs, recovery and archival? | `util/pulse_hybrid_workflow.py` |

Entrypoints delegate to these owners. Scientific runtime code must not import
`agent_workspace`, another worktree, or an old Git checkout. Operational notes,
temporary refactoring candidates and experiment outputs are not runtime inputs.
The adapter module owns shared original/single/three generation; the evaluator
owns cohort selection, view construction, paired predictions and metrics.

## Follow one fixed evaluation

1. `run_experiment.py` resolves a closed YAML bundle and starts
   `run_pulse_hybrid.py`. The latter chooses fixed scheduling, evaluation,
   or optional parameter search explicitly.
2. `run_fixed` verifies source identities and the pinned recovery archive.
   `prepare_fixed_recovery` first restores matching training, then applies
   one common identity gate to whole-center results and record blocks.
3. `make_jobs` builds a finite dependency graph. `run_jobs` admits one
   idle GPU per worker and starts children through the same managed launcher.
4. An evaluator checks the cohort and adapters, renders paired views, and
   commits each complete record. `LiveC5Metrics` registers block identities,
   accumulates newly committed batches, then publishes its provisional summary.
5. `merge_center_blocks` verifies exact coverage and recomputes metrics.
   `summarize_four_centers` performs paired record bootstrap; the launcher
   archives the sealed run only after final validation and closed logs.

The coordinator never loads a GPU model. Training owns optimizer state;
inference owns adapter switching; validation owns immutable identity checks.
The fixed path does not create or consult an Optuna study.

Use the recipe for the intended operation:

| Operation | Experiment entry |
| --- | --- |
| Train and evaluate the fixed recipe | `pulse_full_lora32_pipeline.yaml` |
| Evaluate archived adapters on the full cohort | `pulse_full_lora32_live_eval_20260928.yaml` |
| Resume the verified reboot archive | `pulse_full_lora32_live_eval_20260929_resume4gpu.yaml` |
| Engineering timing / token admission | `pulse_full_lora32_timing_*.yaml`, `pulse_full_lora32_perf_smoke.yaml` |

These files live under `configs/experiments/`. The dated configurations
identify immutable runs, not automatic recommendations to launch them again.

## One comparable evaluation rectangle

For each center, select K unique records after excluding its fixed K500
adaptation identities. `seeded_hash_v1` sorts sample keys by a seeded SHA256
key; it never reads labels to choose records. A larger K extends the same
ordered prefix. Save the selected cohort and full eligible-population digest.

Every selected record receives the same six conditions for all three arms:
clean, Gaussian noise, motion blur, brightness, elastic transform, JPEG.
Each corruption uses a private seed derived from the record and condition.
The five GPU image corruptions are approximations, not an ImageNet-C reference
implementation. The nine training AugMix operators are a separate set.

The workload is **4 centers × K records × 6 conditions × 3 arms = 72K
generated predictions**. The same batch size, prompt, precision, decoding
settings, ordering and tail policy apply to every arm and center. Historical
original-model answers are diagnostic evidence; they cannot replace the
matched original baseline generated by this run.

## Select batch and K without selecting on accuracy

### Original-arm zero-update bypass

`arm_major_original_bypass_v3` is an explicit inference mode derived from
`arm_major_fp16_adapters_v2`. At model load it requires every saved original
LoRA B factor to be exactly zero. Only while evaluating the original arm does
it disable those zero-update branches. The original projector still runs;
single/three adapters still execute, with independently recomputed visual features.
It neither merges nor quantizes weights. PEFT adapter flags, frozen gradients
and reference FP32 parameter storage are restored, including on exceptions.

The `pulse_original_bypass_*.yaml` engineering screens use final 200-step
adapters, batch one and all six conditions. They compare raw tokens and decoded
answers against both the independent author-equivalent reference and the current
v2 implementation. Any mismatch stops before committing that record. In
`performance_batches.json`, `baseline` means v2 and `optimized` means v3;
`reference` is the older independent path. Rotate measurement order and exclude
warmup. Compare v3 with v2 when reporting the incremental gain.

2026-09-30 admission on one RTX 4090, final 200-step adapters, batch one:

| Center | ECGs | v2 seconds/ECG | v3 seconds/ECG | Time reduction |
| --- | ---: | ---: | ---: | ---: |
| Ningbo | 16 | 12.41 | 11.24 | 9.48% |
| Chapman-Shaoxing | 4 | 13.72 | 12.31 | 10.25% |
| CPSC 2018 | 4 | 11.69 | 10.46 | 10.59% |
| Georgia | 4 | 11.36 | 10.44 | 8.15% |

All 504 arm/view outputs have exact tokens and decoded answers against both
references. Across these 28 ECGs, generation time falls from 345.687 to 312.581
seconds (9.58% less time; 10.59% more throughput). These are small engineering
cohorts, not a full-run wall-clock or full-cohort equivalence guarantee. Peak
allocation of 18.42 GiB covers all measured paths, not v3 in isolation.

Evidence and source/config hashes are archived under
`/data/linbinhao/ecg_llm_runs/pulse_original_bypass_v3_20260930/`; see
`audit/performance_summary.json`. The initial interface-guard failure is
preserved separately and contributes no predictions. Regression: 1082 project
tests passed, 236 skipped; 42 dedicated PULSE CPU tests passed.

Running evaluations keep their original source/config identity. Enabling v3 in
a new run requires its own recorded admission; partial old/new result blocks
must not be mixed under the same execution identity.

### Batch and cohort admission

1. Audit the final 200-step adapter artifacts and their source/model identities.
2. Test batches 1, 2 and 4 on the same 16 seeded records per center; include 3
   when memory or throughput makes it useful. Record failures as failures.
3. Admit each actual batch shape, including tails, against the author's
   packing/generation path. Require exact same-batch reference/optimized tokens
   and original-model restoration after adapter switches.
4. Read one timing observation per actual batch from `performance_batches.json`.
   `performance_admission.json` contains per-record parity entries; summing its
   repeated batch durations would overcount time. Warmup is excluded from the
   generation measurements; startup, rendering, IO and validation still count
   toward the wall-clock budget.
5. Freeze batch using throughput, memory and stability. Estimate a common K
   from the slowest center and the remaining deadline, with explicit headroom
   for startup, variance, integrity checks and HDD archival. Do not use F1 to
   choose batch or K. A proposed value is not a measured selection.

The active timing YAMLs are engineering screens. Each managed run retains its
own immutable resolved config; change a subsequent candidate only after the
affected run has exited. Final metrics must come from a complete final run.

## Review results and preserve them

- Inspect the managed manifest and file index, then `hybrid_result.json`.
- Recompute metrics from the paired prediction rectangle, preserving Super5
  order `CD, HYP, MI, NORM, STTC` and mapping hash `555ec85d5b51`.
- Report clean and corruption macro-F1 separately; average conditions and
  centers equally. Include exact-match, Hamming and parse/truncation audits.
- Bootstrap records jointly across arms/views within each center. This does
  not estimate training-seed variation or establish patient independence.
- Keep every checkpoint/config/cohort/source hash. Never fill an old missing
  asset manifest with guessed historical hashes.

Large intermediates go to task-owned shm when capacity permits, otherwise to
the authorized `/data/linbinhao/ecg_llm_runs` HDD namespace. Choose storage before
launching a managed job; do not move its active output or spill onto the nearly
full SSD. Copy, fsync and verify the archive before releasing RAM artifacts.

## Simplification priorities

Pause speculative performance tuning while the retained experiment runs. The
v3 measurements establish a bounded 9.58% generation-time reduction. Historical
last-position projection saved about 0.78-1.08% in its own small probe, without
a stable-speedup claim. Historical merged-LoRA measurements were larger, but
their logits were not bitwise identical and they are not current v3 admissions.
These observations guide engineering effort; they do not establish a hardware
or model performance ceiling. See the active evidence registry for each scope.

Prefer explicit ownership and fewer duplicated rules:

1. Both coordinator entrypoints share `_bind_coordinator_state`. It preserves
   existing operator controls and rejects changed source/config or snapshots;
   each caller still owns its lock, resource policy and job graph.
2. Keep task construction, scheduling and result verification separate. Preserve
   numerical code, data identity, hashes and failure semantics while simplifying.
3. Review retained traditional-training modules before narrowing repository
   scope. Six large modules account for 9,917 lines, but are still referenced by
   retained entrypoints. Shared `core/augmix.py` and `core/consistency.py`
   are directly imported by PULSE, so directory names alone cannot guide removal.

The first startup-state pass reduces tracked production Python from 37,620 to
37,613 physical lines across the same 92 files. Its main benefit is one review
point for the shared state contract. Larger reductions require a dependency-led
scope review; compressing formatting or removing integrity checks is not a goal.

## Safe development loop

Run the canonical launcher with `--dry-run`, check resources, then select free
GPU UUIDs explicitly. At most four task workers may run. CPU tests do not prove
real-model parity. Freeze all scientific source during execution; develop
refactoring candidates in a separate review directory and apply them only
after the affected jobs have exited. Preserve the source snapshots needed to
replay historical checkpoints when numerical implementation identities change.
