ECGFounder 预处理对齐策略

生成日期：2026-05-22 ｜ 适用任务：ECGFounder frozen encoder + PTB-XL Super5 linear probe + PN2021 外部中心评估

核心结论：ECGFounder 适配实验的主线预处理应对齐 ECGFounder 官方 PTB-XL evaluation 输入协议，而不是复用 EfficientNet1DV2 的 100Hz/1000 点输入协议。

主线使用 12 x 5000、10 秒、500Hz 等效输入、PTB-XL records500、per-sample global z-score。滤波链作为 sensitivity analysis 单独跑，不作为主表默认设置。

为什么需要单独对齐

ECGFounder 和我们的 EfficientNet1DV2 baseline 是两套不同输入协议的模型。EfficientNet1DV2 当前主线是 100Hz, 1000 samples, 10 seconds；ECGFounder 官方 PTB-XL evaluation 使用的是 500Hz, 5000 samples, 10 seconds。

如果把 ECGFounder encoder 强行喂入 100Hz/1000 点 ECG，会让它接收到与官方评估和预训练场景明显不同的输入分布，这会削弱 ECGFounder baseline 的公平性。

官方仓库事实

文件 观察到的事实 对我们实验的含义
/root/autodl-tmp/ecgfounder/ptbxl_eval.py 读取 PTB-XL filename_hr，即 records500。输入转成 12 x 5000，做 per-sample global z-score。 PTB-XL linear probe 主线应使用高采样率 500Hz 版本。
/root/autodl-tmp/ecgfounder/tasks.txt 官方 checkpoint 对应 150-class classification validation，不是 PTB-XL Super5。 Super5 对比不能直接用 150-class head keyword pooling 作为主结果。
/root/autodl-tmp/ecgfounder/util.py 提供 50Hz notch、0.67-40Hz bandpass、0.4 秒 median baseline removal。 滤波链可以做消融，但官方 PTB-XL eval 脚本本身没有显式使用这条滤波链。
/root/autodl-tmp/ecgfounder/README.md 提醒验证和微调应遵循 dataset.py 中的 filtering 和 z-score。 需要报告 filtered sensitivity，避免被质疑没有覆盖 README 要求。

主线预处理协议

主线名称：ecgfounder_official_ptbxl_eval_style

用途：ECGFounder frozen encoder + PTB-XL Super5 linear head 的主表结果。

项目 设置
输入 shape (12, 5000)
时长 10 秒
采样率 500Hz 等效输入
PTB-XL 来源 records500 / filename_hr
PN2021 来源 WFDB 原始 ECG，按真实采样率处理后转成 5000 点
导联顺序 I, II, III, aVR, aVL, aVF, V1, V2, V3, V4, V5, V6
标准化 per-sample global z-score，即每条 ECG 在完整 12 x 5000 上计算一个 mean/std
默认滤波 主线不额外加 notch、bandpass 或 median baseline removal

PTB-XL 处理流程

PTB-XL records500 / filename_hr
-> wfdb.rdsamp
-> (5000, 12) 转成 (12, 5000)
-> NaN/Inf 清理
-> 确认导联顺序
-> per-sample global z-score
-> ECGFounder frozen encoder
-> 1024-d feature
-> Super5 linear head

PTB-XL 官方提供 records100 和 records500 两种波形。ECGFounder 官方 PTB-XL evaluation 使用 filename_hr，因此本实验主线使用 records500。

PN2021 处理流程

PN2021 WFDB record
-> wfdb.rdsamp physical mV
-> (T, C) 转成 (12, T)
-> 导联重排到 ECGFounder 顺序
-> NaN/Inf 清理
-> 按真实时间截取前 10 秒
-> 不足 10 秒则 padding 到 10 秒
-> 重采样到 5000 点
-> per-sample global z-score
-> ECGFounder frozen encoder
-> Super5 linear head
-> PN2021 v5 Super5 AUROC/AUPRC

注意：不足 10 秒的 PN2021 ECG 不应直接插值拉伸成 10 秒。更稳妥的做法是按真实时间保留，然后 padding 到 10 秒，再统一重采样或补齐到 5000 点。

滤波消融协议

ECGFounder README 强调 dataset.py 的 filtering，但官方 ptbxl_eval.py 对 PTB-XL 150-class eval 没有显式使用滤波链。因此滤波版不作为主线，而作为 sensitivity analysis。

分支 滤波设置 用途
main 不额外滤波，只做 z-score 对齐官方 PTB-XL eval，作为主表结果
filtered_sensitivity 50Hz notch + 0.67-40Hz bandpass + 0.4s median baseline removal + z-score 回应 README filtering 要求，检查外部中心性能是否敏感

与 EfficientNet1DV2 的区别

模型 输入长度 采样率 默认预处理
EfficientNet1DV2 1000 samples 100Hz minimal_resample + per_sample_global
ECGFounder 5000 samples 500Hz 官方 PTB-XL eval style: records500 + global z-score

两者比较的是模型方案和目标中心适配能力，不要求使用相同输入长度。相反，强行统一到 100Hz 会让 ECGFounder baseline 失真。

实验计划

主线ECGFounder official style

  • PTB-XL fold 1-8 提取 frozen features。
  • 训练 5 类 Super5 linear head。
  • fold 9 选择 best epoch、阈值和可选校准。
  • fold 10 与 PN2021 外部中心评估 AUROC/AUPRC。

消融filtered sensitivity

  • 加入 ECGFounder util.py 滤波链。
  • 保持输入 shape 和 fold 划分不变。
  • 只比较滤波是否改变 fold10 和 PN2021 表现。

建议论文表述

For ECGFounder, we followed its PTB-XL evaluation-style input protocol:
12-lead, 10-second, 500Hz ECGs from PTB-XL records500 were normalized by
per-record global z-score and fed into the frozen ECGFounder encoder.
For PN2021, raw WFDB records were lead-aligned, truncated or padded to
10 seconds, resampled to 5000 samples, globally z-score normalized, and
evaluated with the same frozen encoder and PTB-XL-trained Super5 linear head.
A filtered preprocessing variant following ECGFounder's dataset.py filter
chain was evaluated as a sensitivity analysis.

当前结论

主线应使用 records500 + 12x5000 + global z-score。滤波链不是删除，而是降级为消融。这样既尊重 ECGFounder 官方 PTB-XL evaluation 脚本，又覆盖 README 对 filtering 的要求。
